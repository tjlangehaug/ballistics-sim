## Surprises a future session must know
- `dtolnay/rust-toolchain` does **not** read `rust-toolchain.toml`
  automatically — it selects the toolchain from the action's pinned
  `@rev` (e.g. `@stable`, `@1.89.0`) or from explicit `toolchain`/
  `components` inputs. Since we pin by commit SHA (not `@stable`), I had
  to pass `toolchain: stable` and `components: rustfmt, clippy` by hand
  in `pr.yml`, duplicating `rust-toolchain.toml`. There's a code comment
  at the call site — if `rust-toolchain.toml` changes, `pr.yml` needs a
  matching edit, and nothing will catch that automatically.
- `gate-diff-size`/`gate-test-integrity`/`gate-provenance` only see
  **committed** diffs (`git diff base...HEAD`), same as GitHub Actions
  sees a PR. Running them locally against uncommitted working-tree
  changes will silently show 0 — commit first, then run the gate, same
  as you'd expect from `just verify`.
- Verified all three gates against synthetic diffs (fabricated a 500-line
  file, a removed `#[test]`, an added `#[ignore]`, and a tolerance literal
  change in a `tests/` file) — each failed with the expected message, then
  passed once fixed. No automated test suite was added for the gates
  themselves (they're shell in the justfile, exercised manually this
  session) — worth a `tests/gates/` smoke test in a future CI task if
  gate logic grows more complex.
